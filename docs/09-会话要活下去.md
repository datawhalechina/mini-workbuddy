# 第 9 章　会话要活下去

> 本章代码 `code/ch09/store.py`、`code/ch09/main.py`　·　读完约 4 分钟

## 9.0 记忆存在哪儿

第 8 章最后一句说到，这些记忆只活在进程内存里。根子在模型这一侧——模型是无状态的，它不记得上一轮说过什么。你看到的"它记得"，是框架每次发请求前把整段历史重新拼进去。

这段历史存在 `AgentState` 里，而它只活在内存中。进程一关，全没了。

要解决的就一件事：**把 state 写成文件，下次启动再读回来。**

`Agent` 本身不存记忆，它只有配置，外加一个指向 state 的引用：

```python
Agent(name=..., system_prompt=..., model=..., toolkit=..., state=state)
```

传进去哪份 state，它就接着哪段对话聊；换一份，它立刻变成另一个会话。

## 9.1 存：一个文件

`AgentState` 是 pydantic 模型，自带序列化，不用手写转换函数。

```python
state.model_dump_json(indent=2)      # → 一整段 JSON 字符串
```

配上文件读写，就是完整的存储层（`store.py` 的简化版，省掉了写元信息那几行）：

```python
class JsonStateStore:
    def __init__(self, root: str = ".sessions"):
        self.root = root

    def _path(self, user_id, agent_id, session_id):
        return os.path.join(self.root, user_id, agent_id, f"{session_id}.json")

    def save(self, user_id, agent_id, state):
        path = self._path(user_id, agent_id, state.session_id)
        os.makedirs(os.path.dirname(path), exist_ok=True)
        with open(path, "w", encoding="utf-8") as f:
            f.write(state.model_dump_json(indent=2))

    def load(self, user_id, agent_id, session_id):
        path = self._path(user_id, agent_id, session_id)
        if not os.path.exists(path):
            return None
        with open(path, encoding="utf-8") as f:
            return AgentState.model_validate_json(f.read())
```

一条会话一个文件：

```text
.sessions/<user_id>/<agent_id>/<session_id>.json
```

三层目录回答三个问题：谁在聊、跟哪个智能体聊、聊的哪一段。`session_id` 由 `AgentState` 自动生成一个 32 位十六进制串，也可以自己指定。

对话、任务、权限规则全在这一个文件里，一条会话不到 2 KB。（`tasks` 里装的是 `TaskCreate` 那套任务清单工具维护的条目，本章只用它验证"任务也跟着一起存下来了"。）

> `store.py` 还会多写一个 `.meta.json`（标题、更新时间、消息条数），只给会话列表页用，省得为了列个表把每条会话的完整 JSON 都读一遍。

## 9.2 取：启动时接回去

```python
state = store.load(USER_ID, AGENT_ID, session_id)   # 读文件，没有就返回 None
agent = await build_agent(workspace, state)         # 造 Agent，把 state 递进去
```

`state=None` 时框架自己造一个空 state，等于新会话；读到了，就是接着上次聊。

聊完存一次：

```python
await chat_once(agent, "记住：我的周报固定分三段，进度、问题、下周计划。")
store.save(USER_ID, AGENT_ID, agent.state)
```

下次启动时带上 id，它就知道周报分三段：

```bash
cd code/ch09 && python main.py 8afdedb7b46d431dbe67be1dd71b74ef
```

## 9.3 两个必须注意的地方

**一、每轮存一次，别等退出。**

"退出时存"这个时机不可靠：进程可能被 kill，异常可能直接终止。哪里状态变了就在哪里立刻落盘，最坏也只丢最后一轮。

**二、读回来要清三个字段。**

`store.load()` 读完文件后，多写了三行：

```python
state.reply_context.structured_schema = None
state.reply_context.structured_output = None
state.reply_context.cur_iter = 0
```

序列化是无损的，但"上一轮是对的"不等于"这一轮也是对的"：

- `structured_schema` 是上一轮要求过的输出格式。留着它，恢复后你问一句"今天几号"，模型也会被逼着按旧格式输出 JSON。
- `structured_output` 是上一轮那份结构化结果。留着它，模型会以为这次的结果已经交过了。
- `cur_iter` 是"这一轮走到第几步"。被强杀时它会停在非零值，留着它，Agent 以为这一轮还没结束，会跳过轮次开始时的检查（时间注入、工具状态刷新这类），而且不报错。

工具状态（`tool_context`）相反，要原样保留——清掉它，模型会以为这些工具没注册过，下次调用直接报"未知工具"。

## 9.4 小结

- 模型无状态，记忆全在 `AgentState`；`Agent` 只是壳，随时能重建
- 存：`model_dump_json()` 写文件；取：`model_validate_json()` 读回来
- 一条会话一个文件，用 `user_id` / `agent_id` / `session_id` 三级目录区分
- 状态一变就落盘，别等进程退出
- 读回来清 `structured_schema`、`structured_output` 和 `cur_iter`
